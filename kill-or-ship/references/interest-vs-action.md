# 관심 vs 행동. 약한 신호와 진짜 신호의 차이

가장 자주 일어나는 측정 실수가 관심을 행동으로 착각하는 것이다.
이 문서는 그 차이를 구분하고, 진짜 행동을 측정하는 법을 정리한다.

---

## 신호 강도 스펙트럼

```
약함                                                              강함
좋아요 → 사전등록 → 설문응답 → 카드입력 → 결제 → 재방문 → 추천
```

---

## 약한 신호 (관심)

이런 건 검증의 1차 신호로 쓰면 안 된다. 보조 지표로만 쓴다.

| 신호 | 왜 약한가 |
|---|---|
| 좋아요, 팔로우 | 비용 0. 의향 없어도 누름 |
| 사전등록 (이메일만) | 비용 0. 안 써도 손해 없음 |
| 설문 "관심 있다" | 사회적 바람직성 편향 |
| 인센티브 있는 설문 응답 | 인센티브를 위한 응답 |
| 베타 신청 | 사전등록과 동일 |
| "출시되면 살 거예요" | 미래 자아 과대평가 |

---

## 강한 신호 (행동)

이런 게 진짜 PMF 신호다. 검증의 1차 지표로 써야 한다.

| 신호 | 왜 강한가 |
|---|---|
| 카드번호 입력 | 결제 직전 마찰. 행동 의향 명확 |
| 사전결제 | 실제 돈 지출. 가장 강함 |
| N일 후 재방문 | 필요성 검증 |
| 핵심 기능 사용 완료 | Aha moment 도달 |
| 친구에게 공유 | 가치 확신과 사회적 비용 감수 |
| 대체제 비교나 이탈 | 진짜 고민함 |

---

## 약한 신호를 강한 신호로 바꾸는 법

### 1. 사전등록을 카드번호 받기로

랜딩에 결제 버튼을 추가한다. 카드번호 입력까지 진행시킨다.
직전에 "아직 개발 중입니다. 결제는 출시일에 진행됩니다." 문구를 넣는다.

이게 가능한 이유는 진짜 살 사람만 카드번호까지 가기 때문이다.
사전등록 100명 대 카드 입력 5명을 비교하면, 후자가 더 신뢰할 수 있는 신호다.

### 2. 설문을 인터뷰로

설문 100명보다 인터뷰 5명이 PMF 학습에 더 빠르다.
- 설문은 답을 좁히고.
- 인터뷰는 답을 넓힌다.

특히 "왜 안 쓸 거예요?" 같은 질문은 설문으로 받을 수 없다.

### 3. "관심 있어요"를 이미 돈 내고 쓰는 사람 만나기로

대체제를 유료로 쓰는 사람을 찾는다.
- 영양사 상담 받는 사람.
- 챌린저스 유료 사용자.
- 카카오맵 맛집랭킹을 시간 들여 보는 사람.

이미 돈과 시간을 쓴다는 건 시장이 존재한다는 증거다.
불만이 있다면 기존 해법의 빈틈이 있다는 증거다.

### 4. 베타 신청을 PoC로 행동 측정하기로

백엔드 없이 앞단만 만든다.
- 루틴 앱은 오픈채팅방.
- 큐레이션 서비스는 노션 페이지.
- 매칭 서비스는 폼과 엑셀과 수동 매칭.

사용자가 진짜 쓰는지가 베타 신청보다 100배 강한 신호다.

---

## MVP와 PoC의 차이

자주 헷갈리는 개념이다.

**PoC (Proof of Concept).** 개념이 작동하는지 검증.
- 사용자가 실제로 쓰는지가 핵심.
- 백엔드 없어도 됨. 수동이어도 됨.
- 빨리 만들고 빨리 버리는 게 목적.
- 예: 오픈채팅방, 노션 페이지, 폼과 수동운영.

**MVP (Minimum Viable Product).** 최소한의 제품.
- PoC로 검증된 후에 만드는 것.
- 어느 정도 자동화, 기본 기능 포함.
- 시장에 출시 가능한 형태.
- 예: 백엔드 있는 베타 버전.

순서가 중요하다. **PoC 없이 MVP 만들면 검증 안 된 제품을 정성껏 만드는 함정에 빠진다.**

## 자주 듣는 변명

| 변명 | 진실 |
|---|---|
| "아직 개발이 안 끝나서 행동 측정을 못 해요" | PoC로 가능. 카드번호만 받아도 됨 |
| "유저가 너무 적어서 행동 측정이 의미 없어요" | 100명 약한 신호보다 5명 강한 신호가 더 유의미 |
| "설문 결과로 충분히 알 수 있어요" | 설문은 검증 도구가 아니라 가설 발견 도구 |
| "관심 표명이 많으면 행동도 따라올 거예요" | 따라오지 않는다. 관심과 행동은 다른 변수 |
